# 成语接龙

群里发送“成语接龙”开始合作闯关，默认全群接对 10 次通关。机器人无法在常用词池内给出符合出题规则的下一词时，明确认输并结算，全群提前获胜，不再跳过自己的回合让玩家继续接。

每轮反馈包含双方的成语、当前接字、全群进度、参与人数和本次答题者的贡献。进度过半、最后一棒及通关都有独立提示。答错可重试，不扣已完成的进度；接口故障不算输赢。

一局只有一条接龙链，全群共享：任何人接对一轮就推进一次进度，换个人接着接会继承上一位的结果，而不是各自维护一条链。同一轮里先接对的答案生效，判定和发题期间到达的其他答案不重复计入。

轮次边界使用框架在落库前分配的整数 `dispatch_sequence`：成功发题后保存本群接收水位，水位以内已接收但仍在落库或排队的答案丢弃，之后的新答案正常参与。`received_at` 和数据库消息 ID 不用于判断轮次，因此同一时钟刻度的新答案、清空后复用的 ID 都不会误判。原生桥接的 `sequence` 保留原值；框架序号跨连接保持递增，以适配重连后原生计数归零。水位与分发器标识一并保存，插件重载沿用水位；整个程序重新启动后使用新的序号域，不拿上次运行的大序号过滤新消息。

直接发送答案时，只有恰好四个汉字、且首字等于当前接字的消息才当作答案；艾特机器人时说的成语同样算答案，艾特标签会被剥掉再判定。首字不对或长度不对的普通消息不触发回复，避免打扰群聊。也可以发送 `/接龙 成语` 明确作答，此时首字错误、长度错误和重复都会收到说明。首字正确但不是成语时会提示失败并保留当前题。

## 卡住时的操作

- `接龙提示`：全群每局共享 2 次。首次展示一个可用答案的首尾字，再次对同一题使用时多揭示第二字；提示来自未使用的真实词条，不直接公布完整答案。
- `接龙换题`：全群每局共享 1 次。机器人重新接上一位玩家的成语；开场也可换题，已得进度保留，换掉的成语仍算用过。无其他合适题目时不扣次数。
- `接龙状态`：查看当前成语、进度及剩余帮助次数。`合并接龙` 保留为同义兼容命令。
- `接龙认输`：结束本局并公布最多两个常用参考答案。`退出接龙` 结束本局但不公布答案。

成功发送回复后才推进进度或扣除帮助次数；发送失败保留原状。结算完成后发送“成语接龙”重新开局。

进行中的进度、个人贡献、目标和剩余帮助次数写进成员库的 `room_states` 表（功能名 `idiom_chain`），重启、微信重连或插件重载后可继续，并保留剩余的空闲时间。旧版本的局保留接字及已用词，新增进度从 0 开始，不猜测旧局得分；旧局未记录上一位玩家答案时暂不提供换题。人格对话插件读同一份状态，只据实聊天，不自行出题或结算。

## 出题与判定

规则为四字成语、末字接首字、同字衔接、同一局不重复。机器人从 `lexicon.py` 中维护的常用成语池出题，优先选择后续还能来回接的题目：先按“至少 3 个本局未使用的常用接法”筛选，找不到时逐级放宽到 2 个、1 个，保证玩家始终有解。开场也执行该检查。实在找不到任何可接词时，机器人消耗一次续接（默认 3 次，`bot_rescues` 可调 0–10），以新的开场重新开始本段，全群进度和个人贡献保留；已用词只约束当前这段接龙。常用程度由项目词表约定，不是语料频率评级；可按群内实际体验维护词条。

词条曾与 [chinese-xinhua 成语数据](https://github.com/pwxcoo/chinese-xinhua/blob/master/data/idiom.json) 交叉核对收录情况；这里不打包其词典释义，不依赖在线下载。常用词池并非完整成语词典：认输仅表示机器人在本局词池里确实找不到任何可接词，且续接次数已经用完，不声称汉语里没有任何接法。

玩家答案在常用词池内时本地确认，表外答案交给配置的大模型复核真实性，允许真实但不常见的成语。模型不决定机器人下一词，也不能跳过回合；表外判定仍可能误判。模型故障时保留当前题和分数，等待重试。常用词池内的整局对战无需请求模型接口，运行时仍使用现有模型配置，以支持表外答案。

## 配置

插件配置中的 `idle_seconds`（默认 1800 秒，范围 60–86400）控制空闲多久后自动结束这局。`target_rounds`（默认 10，范围 3–30）设置新局通关次数，修改配置不改变已保存局的目标。无强制每回合倒计时，普通群聊不刷新游戏空闲时间，查询状态也不续时。

`/help` 返回功能菜单。显示名字优先使用本群 `/绑定` 的称呼，其次使用微信名；不会复制其他群的绑定。该功能使用 `llm_config.json`，填写密钥后启用 `idiom_chain` 插件。

插件可单独启停或重载；未结束的局按空闲时间自动结束，不随重启丢失。
